# FNTV Proxy Relay

为 **飞牛影视、Emby、Jellyfin** 提供 STRM 播放代理。支持源站重定向、飞牛同源中继，以及把视频传输放到另一台服务器的媒体直出。支持三服务统一入口：一个主代理容器处理三种协议，一个机房媒体容器共用媒体端口，各服务保留独立密钥和访问限制。

**当前正式版：v0.9.8-relay.5。** 提供 Web 管理界面，支持部署向导、单管理员、配置保存与应用、共享密钥和视频证书管理。管理页直接使用 HTTP，不需要域名、证书或反代。

> 本项目派生自 [jimboo7339/fntv-proxy](https://github.com/jimboo7339/fntv-proxy)。上游未提供明确 LICENSE；公开源码或容器不等于授予再分发或商业使用许可。详见 [NOTICE.md](NOTICE.md)。

## 快速启动 Web 管理

下载 [管理容器 Compose 示例](compose.manager.yaml.example)，在该文件所在目录执行：

```sh
docker compose -f compose.manager.yaml.example pull
docker compose -f compose.manager.yaml.example up -d
```

打开 **`http://服务器IP:18764`**，首次访问设置唯一管理员账号和密码，然后按向导选择播放模式。管理程序默认监听 `0.0.0.0:18764`，示例已配置 `18764:18764` 端口映射；没有 Host 白名单，也不必填写 `-public-url`。

管理页面能打开不等于视频服务已配置完成：按实际需要在 Compose 中发布业务端口、挂载 STRM 目录，再在页面保存并应用。管理端口仅向可信网络开放，数据卷需持久保存。详见 [Web 管理使用说明](docs/WEBUI.md)。现有容器不会自动启用管理入口或迁移配置，首次部署请避免与旧服务端口冲突。

## 选择模式

需要通过网页配置时，见 [Web 管理界面使用说明](docs/WEBUI.md) 和 [管理容器 Compose 示例](compose.manager.yaml.example)。管理入口须显式启用；旧部署入口不变，使用前核对镜像是否包含管理程序。

容器数量不包含媒体服务器本体及已有反向代理。本项目不替代媒体服务器，不管理媒体库，不提供转码。

| 模式 | 本项目容器 | 视频路径 | 入口与指南 |
| --- | --- | --- | --- |
| 原有 302 | 1 | 源站 → 客户端，源站必须对客户端可达 | 默认程序 `stream_mode: redirect`；Emby/Jellyfin 各自 `delivery_mode: redirect` |
| 同源中继 | 1 | 源站 → 主代理 → 原入口 → 客户端；原入口在 VPS 时仍占其带宽 | 飞牛 `stream_mode: relay`，见[中继指南](docs/RELAY_DEPLOYMENT.md) |
| 单容器直出 | 1，双监听 | 源站 → 本容器媒体端口 → 客户端 | 默认程序 `role: all`，见[直出指南](docs/DIRECT_MEDIA.md) |
| 分机直出 | 2，可在不同主机 | 源站 → 机房媒体容器 → 客户端 | 默认程序 `role: proxy` + `role: media`，见[直出指南](docs/DIRECT_MEDIA.md) |
| 三服务统一直出 | 2，可在不同主机 | 三种服务共用机房媒体端口，票据按服务隔离 | 显式使用 `/app/fntv-unified`，见[统一部署指南](docs/UNIFIED.md) |

飞牛 0.9.8 原生 `/v/api/v1/stream` 在 redirect 模式下保留原响应，不能保证每个播放接口都产生 302。同源中继是飞牛功能，不能把其顶层开关当作 Emby/Jellyfin 的同源中继开关。

## 镜像与启动入口

正式版镜像：`ghcr.io/qiwolf/fntv-proxy-relay:0.9.8-relay.5`，发布构建面向 `linux/amd64`、`linux/arm64`。生产建议固定版本，而非依赖可变的 `latest`。

Web 管理入口 `/app/fntv-manager` 支持配置向导、单管理员、密钥与证书管理、保存和应用。默认通过 `http://服务器IP:18764` 访问，无需 HTTPS 或 Host 白名单；原有两套运行入口保持兼容。参见 [本版发布说明](docs/RELEASE-RELAY-5.md)。

```sh
docker pull ghcr.io/qiwolf/fntv-proxy-relay:0.9.8-relay.5
```

**同一镜像包含管理程序及两种代理运行程序，配置格式不能混用：**

默认程序的字段、默认值、单位与三端作用范围见 [配置参数详解](docs/CONFIGURATION.md)。

| 程序 | 如何启动 | 配置 |
| --- | --- | --- |
| `/app/fntv-manager` | 使用上方管理 Compose 示例，显式设置管理入口 | 在 Web 界面配置；管理数据卷持久保存，程序启动本容器内的代理进程 |
| `/app/fntv-proxy` | 镜像默认入口，保留旧部署 | [config.yaml.example](config.yaml.example)，顶层飞牛配置，可选 `emby` / `jellyfin` |
| `/app/fntv-unified` | Compose 设置 `entrypoint: ["/app/fntv-unified"]` | [deploy/unified](deploy/unified)，`role` + `services`，每个服务独立配置 |

统一程序仅支持 `proxy` / `media` 角色，当前定位为直出；不是把旧 YAML 多加一个开关。旧配置默认行为不变，升级镜像不会自动启用统一模式、迁移端口或改写媒体库。

## 推荐：三服务合并、媒体放机房

登录、媒体库和授权：客户端 → NAS 统一主代理 → 对应媒体服务器。视频返回：源站 → 机房统一媒体服务 → 客户端，不经过 NAS 或网页入口 VPS。

- 三个域名可共用一个主代理端口，按 Host 明确分流。Emby 与 Jellyfin 接口路径重叠，不能靠 URL 猜测服务。
- IP 直连保留三个固定端口。同一 IP 的同一端口无法可靠识别三种登录服务。
- 视频统一一个媒体端口，票据绑定服务，各服务密钥、源站允许列表、浏览器来源限制独立。客户端不用填写密钥。
- 两个容器分别部署在各自主机，不是一个容器跨两台机器。只填写机房 URL 不会自动部署远端服务。

完整配置、密钥生成、证书路径、网络映射、反代、升级和回滚见 **[统一部署指南](docs/UNIFIED.md)**。独立代理也可继续使用：[Emby 指南](docs/EMBY_DIRECT.md)、[Jellyfin 指南](docs/JELLYFIN_DIRECT.md)。

## 配置前必须准备

1. 主代理能访问对应服务器，并只读挂载现有 STRM 目录。挂载左侧是代理宿主机实际目录，右侧必须匹配飞牛/Emby/Jellyfin 返回的文件路径，并加入 `allowed_strm_roots`；不是要求左右相同。三端路径不同可将同一源目录映射多次，见 [STRM 挂载详解](docs/STRM_MOUNTS.md)。远程挂载后呈现的 MKV/MP4 不等于 STRM，程序不会迁移媒体库。
2. 机房能访问 STRM 真实源站。两端 `allowed_upstreams` 精确列出主机和非标准端口，每次重定向目标也要允许，不应放开整个内网。
3. 媒体域名、端口映射和防火墙指向机房媒体容器，不能又指回 VPS 或 NAS。浏览器需配置其登录入口的精确 Origin。
4. 两端同一服务使用相同播放密钥，统一模式不同服务使用不同密钥。默认程序可自动生成并持久化；统一程序要求显式密钥文件，不提供自动配对或同步。
5. 用户提供可信证书完整链及私钥，可自定容器内路径或按示例放到 `certs/`。挂载整个证书目录，支持有效证书内容替换后的热加载；**不包含自动签发、续期或同步**。路径改变需重启。

媒体服务无登录页面；无有效票据的取流被拒绝。鉴权不能隐藏开放端口或 TLS 握手，也不能替代网络运营方的服务许可。

## 能力与边界

支持 GET/HEAD、Range/If-Range、范围响应透传、限时加密票据、重定向目标校验、STRM 目录边界检查和证书热加载。Emby/Jellyfin 静态播放按当前用户向原服务器核验权限，返回兼容客户端拼接行为的相对入口，再跳转机房。

**直出不等于转码迁移。** 本地文件、客户端不支持的编码、转码、直播和 HLS/DASH 分片不保证绕过原服务器；字幕、图片也可能走原入口。媒体端不负责转码。票据是限时访问凭证，已签发票据不会随账号权限撤销立即失效，不要公开完整播放 URL。

三种服务已在独立与统一部署中完成现场 STRM 客户端播放验证，并核对机房连接及流量；不代表所有客户端、片源、IPv6、长时播放和并发性能均验收通过。仅容器 `Up`、接口 `302/206` 不能替代实际起播、拖动和数据路径检查。

## 升级与故障排查

先备份配置、Compose、密钥及原镜像版本，空闲端口并行测试，三端通过后再切换入口。保留旧容器供回滚，不覆盖旧密钥。默认模式票据与统一模式带服务范围的票据不兼容，切换后需退出影片重新播放。详见[升级和回滚](docs/UNIFIED.md#升级和回滚)。

播放失败依次检查：是否连接主代理而非媒体端口；条目是否真正为 STRM；是否转码；挂载和允许列表；媒体证书、映射及网页 Origin。不要通过禁用证书校验或放开所有源站排错。旧 302 逻辑及调试日志可能含源站 URL，不承诺所有历史日志均脱敏；限制日志访问并在提交问题前去掉登录令牌、源站密码和完整签名 URL。
