# v0.9.8-relay.2

本正式版在保留历史 302、飞牛同源 relay 和单机/分机直出的基础上，加入 Emby、Jellyfin 媒体直出及三服务统一部署。

## 新增与修复

- Emby/Jellyfin 对符合条件的 STRM/远程静态媒体签发限时机房媒体地址，播放授权仍由原服务器和当前用户控制。
- 使用相对 `DirectStreamUrl` 跳转入口，修复客户端再次拼接绝对服务器地址后 404、回退原服务器的问题。
- 一个主代理容器支持三种适配器：共享端口按 Host 分流，同时保留三个固定端口供 IP 直连；不根据重叠 URL 猜测 Emby/Jellyfin。
- 一个媒体容器共用一个端口，票据绑定服务范围，各服务独立密钥、回源白名单及浏览器 Origin。
- 保留默认程序的密钥自动生成/持久化、显式共享密钥文件和媒体证书热加载。统一程序使用显式服务密钥文件。

## 镜像和启动

固定镜像：`ghcr.io/qiwolf/fntv-proxy-relay:0.9.8-relay.2`，发布构建面向 amd64/arm64。

默认入口仍为 `/app/fntv-proxy`，旧配置默认行为保留。统一部署必须显式使用 `/app/fntv-unified` 和新的 `services` 配置，见 [UNIFIED.md](UNIFIED.md)。同一镜像分别在 NAS 和机房启动两个容器，不是一个容器跨两台主机。仅拉取镜像不会自动接管现网端口。

历史 `v0.9.8-relay.2-rc.1` 不含 Emby/Jellyfin 直出与统一入口；不要向旧镜像套用新配置。版本标签是固定快照，当前主分支可能继续演进，应以对应标签文档和示例为准。

## 验证范围与限制

已完成飞牛、Emby、Jellyfin 独立及统一部署的现场 STRM 实播验证，核对机房媒体连接、范围响应与字节增长，确认验证样本的视频不由 NAS/VPS 中转。不能推断所有客户端、片源、IPv6、长时播放或并发压力均验证通过。

本项目不迁移媒体库，不自动转换挂载视频为 STRM，也不把转码迁到机房。普通文件、转码、直播/HLS/DASH、字幕和图片可能仍走原服务器。客户端失败应核对实际播放类型及请求地址，不能仅凭成功播放或 206 判定直出成功。

证书由用户提供，支持指定路径/目录挂载及有效证书内容热加载；**没有证书自动签发、续期或同步**。统一两端同一服务必须安全共享相同密钥，客户端无需配置该密钥。

## 升级提示

先备份配置、密钥和旧镜像版本，空闲端口并行验证，再切换入口。旧单服务票据与统一服务范围票据不兼容，迁移后需重新播放。保留旧容器和端口规则供回滚，不覆盖原密钥。完整步骤见 [统一指南](UNIFIED.md#升级和回滚)；仅使用旧部署见 [DIRECT_MEDIA.md](DIRECT_MEDIA.md)。

许可证状态未改变，参见 [NOTICE.md](../NOTICE.md)。
