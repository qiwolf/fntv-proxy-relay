# v0.9.8-relay.6 — PlaybackInfo 响应处理与相对媒体地址兼容

PlaybackInfo 非 2xx 响应直接透传，不再进入 JSON 解析；2xx 空体和纯空白体原样保留，避免误报解析失败。上游返回的真实 400 仍按 400 返回。

新增脱敏诊断字段：状态码、请求声明长度、响应长度、已耗时和处理结果。非 2xx 的响应长度使用上游声明值，未知时为 -1；请求声明长度不能证明请求体已完整送达。新增观测不包含地址、媒体标识、参数、请求头或正文。

新增可选配置 `stream_api_relative_base_url`，省略时关闭。仅解析 `/v/api/v1/media/range/` 下的规范根相对地址，基础来源必须由本地配置指定且已列入 `allowed_upstreams`；拒绝路径混淆、跨来源和不受信任地址。

该配置提供兼容能力，不能将飞牛媒体接口自动变成 CloudDrive2 直链，也未证明可以改善实际播放性能。启用前需单独验证媒体节点回源、认证、分段请求和播放路径。详见 [相对地址说明](STREAM_API_RELATIVE_URLS.md)。

本版本保留 relay.5 的管理入口、Jellyfin 支持、STRM 目录映射及服务启动逻辑。升级不自动启用管理或相对地址功能。

验证：本地全量 Go 测试、竞态检查、静态检查及独立复审通过。旧基线隔离测试已覆盖响应透传、票据分段请求和恶意地址拒绝；真实客户端播放仍需部署后另行验收。

镜像：`ghcr.io/qiwolf/fntv-proxy-relay:0.9.8-relay.6`，发布流程构建 linux/amd64 和 linux/arm64。
