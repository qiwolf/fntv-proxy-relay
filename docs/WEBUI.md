# Web 管理界面使用说明

管理界面用于配置、保存和启动播放代理，不替代飞牛影视、Emby、Jellyfin，不管理影片库或转码。管理账号只管理本程序，与媒体服务器账号无关。

本文对应 `0.9.8-relay.5`，包含 `/app/fntv-manager`，支持 HTTP 直接访问。旧版镜像 `0.9.8-relay.3` 不包含管理入口。管理功能为显式启用，原镜像默认入口 `/app/fntv-proxy` 保持不变。现有部署不会自动迁移。

## 1. 隔离启动与持久化

仓库根目录提供 [compose.manager.yaml.example](../compose.manager.yaml.example)。它使用正式镜像，显式选择管理入口，不挂载 Docker socket。管理进程直接启动同一容器内的代理子进程，无需操作其他容器。

```sh
docker compose -f compose.manager.yaml.example pull
docker compose -f compose.manager.yaml.example up -d
```

启动后打开 `http://服务器IP:18764` 即可设置管理员，无需域名、证书或反代。按文件注释配置需要发布的业务端口和 STRM 挂载。示例不替换旧容器，不能与旧服务占用同一个宿主机端口。

`/data/management` 必须使用可写持久卷，里面有管理账号密码哈希、配置及历史版本、共享密钥、证书私钥、运行版本快照。整个卷都按秘密资料保护。不要提交 Git、公开共享或放进普通日志；备份时停止管理进程并完整备份持久卷，恢复时保持私有权限。普通配置导出不等于完整灾备，不包含所有秘密。

STRM 目录只读挂载，管理数据卷可写。程序不会代建宿主机端口映射、同步 STRM、建立网络隧道或挂载远程盘；这些仍由 Docker/宿主机及路由器负责。创建部署环境是一次性基础工作，后续账号、配置、密钥和证书可在界面管理。

## 2. 管理入口与首个管理员

默认监听 `0.0.0.0:18764`，Docker 映射 `18764:18764` 后直接打开 `http://服务器IP:18764`。这是管理页面端口，不是影视登录或视频传输端口；若修改映射左侧端口，访问时使用修改后的端口。

IP、主机名和域名均可访问，无需配置 Host 白名单或 `-public-url`。HTTP 为默认方式，不要求 HTTPS 反代。程序自动拒绝跨站浏览器请求，管理员登录仍为必需；这些防护不需要额外配置。若自行使用反代，应保留客户端请求的 Host（包含非默认端口）。

HTTP 不加密密码和管理数据，建议仅在可信内网或 VPN 使用，不直接向互联网开放管理端口。这不影响局域网直接部署。

**在管理员创建完成前，仅允许本人可信网络访问。** 首次访问者可以创建唯一管理员，不能先把空白安装公开再稍后设置。首次设置后不能再创建第二个管理员。设置完成仍建议保留管理入口的网络访问限制。

管理员密码至少 12 个字符，且不超过 72 个 UTF-8 字节，中文字符占多个字节。程序保存密码哈希，不保存明文。登录会话仅保留在页面内存，刷新可能需要重新登录；不要与他人共用登录页面。修改密码需要原密码，新密码生效后需重新登录。管理服务重启后已有会话不再有效。不存在默认管理员密码，也没有媒体服务器账号自动迁移。

## 3. 先选择播放模式

| 模式 | 视频实际路径 | 当前能力与限制 |
| --- | --- | --- |
| 302 直链 | 视频来源 → 客户端 | 飞牛、Emby、Jellyfin；客户端必须能访问视频来源。飞牛原生部分接口保留原响应，不保证所有接口产生 302。传统多服务各用独立入口端口，不使用共享域名路由。 |
| 原入口转发视频（同源中继） | 视频来源 → 原入口代理 → 客户端 | 当前只支持飞牛；Emby/Jellyfin 组合会被拒绝。原入口在 VPS 上时仍占用 VPS 带宽。 |
| 单容器直出 | 视频来源 → 本容器视频端口 → 客户端 | 当前每个管理实例只选一个服务；主代理入口和视频监听端口分开。不能配置三服务单容器双总端口。无需两端交换包。 |
| 分机直出 | 视频来源 → 媒体服务 → 客户端 | 主代理和媒体服务分别运行，可同机或异地；支持三服务统一入口与独立服务密钥。只有此模式需要选择主代理/媒体服务角色。 |

管理模型与真实运行 YAML 分开保存，由程序选择传统或统一运行入口并验证。不支持的组合不能通过保存或应用绕过限制。传统多服务使用相同 STRM 目录映射；需要每服务不同映射时使用分机统一模式。

## 4. 服务地址、入口和端口

“服务器地址”填写主代理能访问的飞牛影视/Emby/Jellyfin 原服务地址；“登录入口”是客户端连接代理的位置。视频公网地址用于播放，不用于登录。

监听端口是容器内程序端口，默认绑定 `0.0.0.0`，可在高级设置修改。bridge 网络需额外发布端口；host 网络直接占用宿主机端口。`0.0.0.0` 只表示 IPv4，IPv6 应明确使用 `::` 并核对 Docker、系统和防火墙支持。公网端口可以与容器端口不同，视频公网地址必须填写客户端实际访问的域名和公网端口。

统一分机主代理可按域名区分服务，或为 IP 访问配置各服务独立端口；不能仅凭共享 IP 猜测目标服务。媒体服务不需要登录入口、原媒体服务器地址或 STRM 挂载。

## 5. STRM 目录与视频来源

主代理读取 STRM 文件时，需要对应的本地或同步副本。每组目录填写：

- 来源目录：飞牛影视/Emby/Jellyfin 返回的 STRM 路径所在目录。
- 本地目录：主代理容器内可以读取的对应目录，不是未挂载的宿主机路径。

例如 Emby 中为 `/media/movies/a.strm`，主代理副本在 `/strm-copy/movies/a.strm`，填写来源 `/media/movies`、本地 `/strm-copy/movies`。在 Compose 中将实际宿主机副本目录只读挂到 `/strm-copy/movies`。子目录自动对应，无需每部影片添加规则；多个独立挂载才添加多组。两台机器不要求宿主机路径相同，媒体服务完全不需要这些副本。

运行字段为 `strm_directory_map`，最长目录前缀优先匹配；路径边界、遍历、符号链接逃出允许目录会受到限制。映射目标必须在允许的本地 STRM 根目录内，文件需可读。映射不会同步文件，也不会改写 STRM 里的视频 URL。

“STRM 视频来源”填写文件内视频 URL 的主机及端口，如 `http://video.internal:19798/dav/movie.mkv` 填 `video.internal:19798`，不填完整路径或账号密码。它限定代理可以取视频的服务器，不是用户权限列表，也不是影视登录地址。分机媒体服务必须能够实际访问该来源。

## 6. 共享密钥与加密配置包

先保存已选服务配置，再生成密钥；生成仅补齐缺少的密钥，不覆盖已有密钥。302 和同源中继不使用分机交换流程。单容器直出在本机管理密钥。

分机模式在主代理生成密钥后导出媒体服务配置包，设置至少 12 字节的独立包口令。包采用 scrypt 派生密钥与 AES-256-GCM 加密，包含所选服务、视频来源限制及对应共享密钥；不包含账号密码、证书私钥、登录地址或 STRM 目录。包与口令应分别传递。

在媒体服务导入后，核对监听端口、公网地址、连接方式，再保存并应用。导入预设媒体监听 `0.0.0.0:49967`，不是自动检测的生产端口。已有不同密钥会拒绝整个密钥导入，不会静默覆盖。相同密钥可重复导入。导入配置不代表已成功启动，配置保存与应用仍需确认；客户端不需要手动配置共享密钥。

## 7. 视频 HTTPS 证书

直接由视频服务提供 HTTPS 时，通过上传或粘贴提交 PEM 证书链和匹配的私钥；程序检查配对、访问域名及有效期后私有保存。上传失败保留旧证书。状态只显示域名、到期时间及指纹，不回传私钥。

端口映射不提供 TLS，IPv6 直连也不免除 HTTPS 证书要求。使用 IP 访问时证书必须覆盖该 IP，且客户端信任签发方。证书覆盖域名而非端口。使用已有 HTTPS 反代时，证书放在反代，视频服务可选择明确的内部 HTTP 连接方式，并限制内部端口可达范围。

程序**不自动签发、续期或同步证书**；日期和域名校验也不代表公网证书链一定被所有客户端信任。证书更新后应用配置，检查真实客户端连接。管理站点 HTTPS 证书与视频服务证书是不同用途，上传视频证书不会给管理监听自动启用 HTTPS。

## 8. 保存、应用、恢复与验收

保存配置是持久化编辑结果，不等于改变当前播放进程。应用会生成独立运行版本，先验证配置和所需材料，再停止旧进程、启动新进程；会短暂影响播放。启动失败时尝试恢复上次运行版本，恢复也失败则明确报错，不宣称已回滚成功。

程序重启只恢复上次成功应用的配置及材料，不会自动应用后来仅保存的修改。配置历史恢复也应先查看、确认并应用。不要手改运行版本目录，里面可能含密钥和证书私钥。

“运行中”及端口检查只证明进程与监听状态，不代表播放验收。每次首次部署/模式切换应使用实际客户端登录、播放 STRM、拖动进度，再播放普通文件；分别确认 302 直达来源、同源经过原入口、直出经过视频端口。还应检查证书信任、错误密钥拒绝、未授权来源拒绝，以及路由器映射/防火墙/SNAT 是否符合实际网络。

## 9. 启动参数

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `-listen` | `0.0.0.0:18764` | 管理 HTTP 监听，必须为 IP:端口；IPv6 可设为 `[::]:18764` |
| `-public-url` | 空 | 旧参数仅保留启动兼容，不再参与访问限制，无需填写 |
| `-data-dir` | `./management-data` | 私有持久数据目录 |
| `-legacy-binary` | `/app/fntv-proxy` | 传统模式运行程序 |
| `-unified-binary` | `/app/fntv-unified` | 分机统一运行程序 |

不要把本说明当作已对你的生产环境完成部署的记录。上线前请保留原容器及配置备份，在独立端口验证后再切换入口。
