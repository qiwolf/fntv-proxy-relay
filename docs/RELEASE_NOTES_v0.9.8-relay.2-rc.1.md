# v0.9.8-relay.2-rc.1

专用媒体直出预发布版。保留旧 302、同源 relay 和独立 Emby 代理；旧配置默认不启用新端口。此次不更新稳定版 latest。

## 新增

- `role: proxy/media/all` 与 `delivery_mode: direct`：页面/登录保留原入口，支持媒体数据从另一公网出口返回。
- AES-256-GCM 限时票据、GET/HEAD/Range、精确 CORS 来源及逐跳上游允许列表。
- 单机 all 模式自动生成并持久化播放密钥；分机部署须安全配置同一密钥。
- 用户通过 `media.tls_cert_file` 和 `media.tls_key_file` 指定完整证书链和私钥；容器示例使用 `/run/certs/fullchain.pem`、`/run/certs/privkey.pem`，支持自定义挂载及容器内路径。
- 固定路径证书内容热加载，错误新证书保留旧有效证书，不打断已建立连接。

不包含证书自动签发、续期或同步。必须由用户提供客户端信任且匹配域名的有效证书，并在到期前更新。客户端不需要安装本程序的密钥。

## 安装与升级

```sh
docker pull ghcr.io/qiwolf/fntv-proxy-relay:0.9.8-relay.2-rc.1
```

支持 linux/amd64、linux/arm64。完整步骤及带注释配置见 [直出部署指南](DIRECT_MEDIA.md) 和 [部署示例](../deploy/direct)。证书目录整体只读挂载；密钥数据目录必须持久化，升级时保留。单独绑定证书文件可能妨碍原子替换后的热加载。

启用直出前备份旧配置并保留旧镜像；回滚到 `role: proxy`、`delivery_mode: proxy` 后重新获取播放地址。旧模式用户只更新镜像不会自动开启直出。媒体服务不可达时不会自动回退占用 VPS 带宽。

## 验证与边界

Go race 测试、vet、旧模式回归、票据拒绝、Range/HEAD、跨域、证书更换与错误证书保护、容器重建后密钥复用均已验证。现场实际播放由用户确认，日志与连接证据确认地址改写、206 及专用媒体端口持续传输；原影视反代不再承载该媒体连接。

客户端自身的 VPN/网络代理仍可能中转数据，媒体域名需按需设置 DIRECT。HLS/DASH 清单递归改写、所有客户端兼容性、长时间播放、现场拖动和并发压测未宣称全面通过。票据过期后的拖动/重连须重新取得地址。

无票据请求断开不等于端口不可识别，也不保证符合机房规定。继续遵守 [NOTICE](../NOTICE.md) 中的上游许可边界。
