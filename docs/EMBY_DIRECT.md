# Emby 分机媒体直出

本功能包含在正式版 `v0.9.8-relay.2`。历史 `v0.9.8-relay.2-rc.1` 不包含此功能；不要仅向旧镜像添加配置就认为已启用。本指南使用镜像默认 `/app/fntv-proxy` 入口；需要三服务合并并独立密钥隔离时使用 [统一指南](UNIFIED.md)，其配置格式不同。

NAS 保留 Emby 和主代理，负责登录、媒体库、播放授权及签发地址；机房媒体服务读取源站并向客户端传输视频。媒体服务不必和 Emby 同机，也不需要挂载 STRM 目录。

```text
登录、媒体库、播放授权：客户端 → Emby 主代理 → NAS Emby
符合条件的视频数据：  客户端 → 机房媒体服务 → 机房源站
```

兼容 Emby 客户端时，`DirectStreamUrl` 必须是主代理上的相对跳转入口，不能直接填入完整机房 URL：Emby 4.10 网页客户端会无条件拼接服务器地址。相对入口只返回 `302` 到机房签名地址，不传输视频。`Path` 可以保留完整签名地址；客户端最终请求的视频必须到达媒体节点。

## 两种模式和适用范围

| 配置 | 行为 |
| --- | --- |
| `emby.delivery_mode: redirect`（默认） | 保留原有 Emby 302 行为，客户端直接访问源站；客户端必须能到达源地址。 |
| `emby.delivery_mode: direct` | 对符合条件的远程媒体或 STRM 静态播放签发加密、限时媒体地址，由机房媒体服务传输。 |

`emby.delivery_mode` 独立于顶层 `delivery_mode` 和 `stream_mode`；后两者仍控制飞牛影视。启用 Emby direct 不会自动改变飞牛影视模式。

这不是把所有 Emby 流量迁出 NAS。本地真实文件、转码、直播/HLS，以及字幕、图片、媒体库等请求仍按 Emby 原路径处理。客户端不支持原视频格式而触发转码时，视频仍可能经过 NAS。验收时必须确认播放类型和实际连接，不能只看容器启动成功。

## NAS 主代理

使用 [配置示例](../deploy/emby-direct-proxy/config.yaml.example) 和 [Compose 示例](../deploy/emby-direct-proxy/compose.yaml)。在仓库的 `deploy/emby-direct-proxy` 目录复制配置后修改实际参数：

```sh
cp config.yaml.example config.yaml
docker compose pull
docker compose up -d --no-build
```

启动前必须完成以下准备：

- 将 `emby.target` 指向原 Emby。本示例为 NAS 的 `127.0.0.1:8097`；不是默认的容器内部 `8096`。
- 将 `emby.listen` 改成 NAS 的实际地址及空闲测试端口；示例 `192.0.2.10:18097` 不占用原入口。当前程序同时启动飞牛监听，所以将不用的飞牛入口绑定 `127.0.0.1:28006`，不要向外开放。
- 修改 Compose 左侧 STRM 宿主机目录。右侧 `/mnt/strm` 必须匹配 Emby 在播放信息中返回的绝对路径，并加入 `allowed_strm_roots`。只读挂载，不必修改 STRM 文件内容。读取会检查目录边界和符号链接，越界会拒绝。
- `allowed_upstreams` 填真实媒体源的主机及端口；`strm_path_map` 仅用于改写 STRM 内容中的 URL，不用于修复文件挂载路径。
- `media.public_base_url` 填客户端可达的机房媒体服务 HTTPS 地址；`media.token_key_file` 指向与机房媒体服务完全相同的密钥文件。文件权限 `0600`，不可提交到 Git，也不要在两端分别自动生成。

此代理使用 `role: proxy`，NAS 不启动媒体监听，也不需要媒体 TLS 证书。先在可信内网测试 HTTP 入口；公网正式网页入口仍应使用 HTTPS。不要直接把明文测试端口暴露到互联网。

## 机房媒体服务

可以复用现有 `role: media` 节点，无须为每个 Emby 再建一个媒体容器。参见 [分机部署指南](DIRECT_MEDIA.md) 和 [媒体节点配置](../deploy/direct/media.config.yaml.example)。复用前确认：

- NAS 签发端与该节点共享同一密钥，节点能访问源站。
- 两端的源站白名单均允许实际源地址；媒体节点还会检查回源重定向目标。不要为方便直接开放所有目标。
- 公网端口映射指向机房媒体服务器，而不是 NAS。客户端到媒体节点的路由也不能绕回带宽受限的 VPS。
- 浏览器播放时，将 Emby 网页的精确 Origin 加入媒体节点 `media.allowed_origins`，保留已有飞牛网页条目。Origin 包括协议、主机和非默认端口，不包含路径。跨域许可不是用户鉴权。

共享密钥意味着这些签发端属于同一信任域；若需隔离，使用独立媒体实例，或切换到统一程序的服务范围票据及独立密钥。共享旧媒体节点不代表旧主代理镜像已经支持 Emby direct。

媒体节点由用户提供有效证书：通过 `media.tls_cert_file` 和 `media.tls_key_file` 指定容器内路径，并挂载整个证书目录。原路径替换有效证书后支持热加载；修改路径需要重启。程序不自动签发、续期或同步证书。域名须匹配证书，客户端无需配置共享密钥或导入私有证书；使用 IP 时也必须有受客户端信任且包含该 IP 的证书，不能用关闭校验代替。

## 授权与安全边界

签发建立在 Emby 的播放授权上；静态视频请求会使用当前调用者凭据向 Emby 核验，不能用其他用户的缓存结果获得权限。签发失败或源站不被允许时拒绝请求，不回退暴露原始内网源 URL。

媒体票据本身是限时访问凭据：拿到完整地址的人可在有效期内访问对应媒体。`media.token_ttl_seconds` 默认 3600，范围 1–86400 秒；过期后的拖动、新分段或重连可能需要重新取得播放地址。不要分享票据、记录完整播放 URL 或把它放入公开故障截图。Emby 权限撤销不等于已签发票据立刻失效；有效期应按实际需求设置。

## 验收与回退

先让客户端连接独立测试入口，选择一部已授权的 STRM 视频，确认开始播放和拖动均正常。检查播放信息中的媒体地址指向机房媒体端点，不含源站账号或内网 URL；检查媒体节点返回有效的范围响应（通常为 `206`），并通过连接或流量观察确认视频由机房发出。

同时测试未登录/无权限用户无法获得播放票据，错误或过期票据不能回源；再检查一部本地文件或需要转码的视频仍走 Emby 原流程。接口检查不能替代真实客户端的开始播放和拖动验收。

不切换原正式入口时，停止此独立测试 Compose 即可回退，不影响原 Emby 或飞牛影视。需要保留代理但恢复历史 302 时，改为 `emby.delivery_mode: redirect` 并重建该代理；此模式要求客户端可以直接访问源站。
